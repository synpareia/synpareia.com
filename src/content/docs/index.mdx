## A concrete example

Crew A produces a research draft. Crew B reviews it and signs the review *against A's draft* — a single chain that both Crews appended signed blocks to, each with their own private key.

Either Crew can hand the chain bytes to a third party — a customer, an auditor, a different agent — who verifies the entire exchange offline against the Crews' published public keys. Neither Crew's word is required. Neither Crew can rewrite history after the fact. **A third party can prove who said what without trusting either side's logging.**

That's the shape synpareia gives every multi-agent system, regardless of which framework you build with.

## Quick taste

<Tabs>
  <TabItem label="Two agents, verifiable interaction">
    ```python
    import synpareia

    # Each agent owns its private key. No registration.
    alice = synpareia.generate()
    bob = synpareia.generate()

    # A bilateral chain — both agents are named signatories.
    chain = synpareia.create_chain(
        alice, policy=synpareia.policy.templates.sphere(alice, bob)
    )

    # Alice appends a signed block. Bob does the same later.
    chain.append(synpareia.create_block(alice, "message", "Draft research findings."))
    chain.append(synpareia.create_block(bob, "message", "Reviewed: agree with findings."))

    # A third party with just the chain bytes can verify both signatures.
    valid, errors = chain.verify(
        public_keys={alice.id: alice.public_key, bob.id: bob.public_key}
    )
    assert valid
    ```
  </TabItem>
  <TabItem label="Independent assessment">
    ```python
    import synpareia

    # Each agent commits to its assessment before either reveals.
    # Cryptographic proof that neither saw the other's first.
    alice_hash, alice_nonce = synpareia.create_commitment(b"alice's assessment")
    bob_hash, bob_nonce     = synpareia.create_commitment(b"bob's assessment")

    # Both publish their commitment hashes. Then both reveal content + nonce.
    # Anyone can verify the reveal matches the original commitment.
    assert synpareia.verify_commitment(alice_hash, b"alice's assessment", alice_nonce)
    assert synpareia.verify_commitment(bob_hash,   b"bob's assessment",   bob_nonce)

    # Either side trying to change its assessment after seeing the other's
    # would produce a hash that doesn't match — anchoring bias is provable.
    ```
  </TabItem>
  <TabItem label="Portable proof">
    ```python
    import synpareia
    from synpareia.policy import templates

    # Build a small two-agent chain to export.
    alice, bob = synpareia.generate(), synpareia.generate()
    chain = synpareia.create_chain(alice, policy=templates.sphere(alice, bob))
    chain.append(synpareia.create_block(alice, "message", "Hello from Alice"))

    # Export as self-contained JSON. The recipient verifies offline,
    # no synpareia access needed.
    export = synpareia.export_chain(chain)
    valid, errors = synpareia.verify_export(
        export, public_keys={alice.id: alice.public_key, bob.id: bob.public_key}
    )
    assert valid
    ```
  </TabItem>
  <TabItem label="What tampering looks like">
    ```python
    import synpareia
    from synpareia.policy import templates

    alice, bob = synpareia.generate(), synpareia.generate()
    chain = synpareia.create_chain(alice, policy=templates.sphere(alice, bob))
    chain.append(synpareia.create_block(alice, "message", "Alice's draft"))
    chain.append(synpareia.create_block(bob,   "message", "Bob's review"))

    # Honest verification: passes.
    assert chain.verify(public_keys={
        alice.id: alice.public_key, bob.id: bob.public_key,
    })[0]

    # Attacker swaps Bob's published key for one they control.
    # Bob's signed block fails verification — the chain is unverifiable.
    attacker = synpareia.generate()
    valid, errors = chain.verify(public_keys={
        alice.id: alice.public_key, bob.id: attacker.public_key,
    })
    # valid = False
    # errors = [..., signature verification failed on Bob's block]
    ```

## How synpareia relates to other primitives

If you've worked in cryptographic identity before, here's where synpareia sits.

| Primitive | What it does | When to use synpareia instead / alongside |
|-----------|-------------|------------------------------------------|
| **DIDs / Verifiable Credentials** | Decentralized identifiers + claim envelopes | Synpareia profiles *are* DIDs (`did:synpareia:<sha256(pk)>`). VCs attest static facts about an agent. Synpareia chains attest *sequences of agent actions*. Complementary; use both. |
| **Sigstore / cosign** | Signs build artefacts with ephemeral keys + transparency log | Sigstore is for software supply chain. Synpareia is for runtime agent interactions. Different scope. |
| **Append-only logs (Git, transparency logs)** | Hash-linked, append-only sequence | Same shape, agent-flavoured. Synpareia chains are per-agent and portable; transparency logs are typically shared and centrally hosted. |
| **Blockchain** | Distributed ledger with consensus | Synpareia chains are per-agent. No consensus, no mining, no fees. Each agent owns and serves its own chain; cross-chain references are explicit anchors, not a shared ordering. |
| **OAuth / agent-to-server auth** | Delegated authorization | Different problem — synpareia is about agent-to-agent trust, not user-to-platform. Use OAuth for the human boundary; use synpareia for the agent boundary. |

## Status

**Stable** (1.0-track, semver from here on):
- **Tier 1** — block / chain / anchor primitives (`synpareia.create_chain`, `synpareia.create_block`, `synpareia.create_anchor_block`)
- **Tier 2** — witness timestamp seals, blind conclusions (`synpareia.witness.*`)
- **Tier 3** — chain policy primitives, multi-party negotiation (`synpareia.policy.*`, `synpareia.proposal.*`)
- **Profile directory** — A2A-compatible agent cards with sigauth (`synpareia.profile.*`)

**Evolving** (may shift before 1.0):
- **Tier 4** — signed reputation envelopes (`encode_signed` / `decode_signed`)
- **Public synpareia network** — matching, conversation relay, payments. Not yet deployed publicly.

The SDK is at 0.5.1; the Trust MCP at 0.5.0. The two ship together and pin floors against each other.

## What synpareia is NOT

- **Not a chatbot platform** — agents are the primary users; humans are sponsors and auditors
- **Not an inference provider** — synpareia routes and attests; agents bring their own models
- **Not a marketplace** — interactions are the product, not tasks-as-jobs
- **Not a blockchain** — hash-linked chains *per agent*, not a shared distributed ledger
- **Not a credential issuer** — synpareia attests interactions; for static identity claims, use Verifiable Credentials alongside
